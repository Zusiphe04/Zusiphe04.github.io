# 2. User Stories and Tasks — Reflection

## Situation
Developing LocalPro required translating complex marketplace needs into clear, actionable development tasks. The platform needed to support two distinct user journeys: customers searching for service pros and filling out quote requests, and business owners managing their listings and reviews. Without structured user stories, development could easily lose focus on core customer outcomes.

## Task
My task was to define student-centred user stories using standard Agile syntax (**"As a... I want... so that..."**), establish clear acceptance criteria (AC) for each epic, break down implementation tasks (T), and link completed user interfaces (such as the homepage search header, step-by-step quote wizard, and business review views) to visual evidence.

## Action
I structured our user stories across core functional epics: directory browsing, quote request workflows, business profiles, and reviews. For each story, I wrote 4–6 specific acceptance criteria covering successful executions, validation checks, and edge cases. I captured interface screenshots of the quote request wizard modal and business listing reviews, linking each directly to its corresponding user story block to ensure end-to-end requirement traceability.

## Result
The resulting user story framework provided a clear blueprint for implementation and testing. Connecting each acceptance criterion to concrete UI evidence made it easy to demonstrate feature completion. I learned that well-structured user stories bridge the gap between user expectations and technical execution, keeping developer efforts focused on real user value.
