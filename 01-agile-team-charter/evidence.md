## 1.1 LocalPro Agile Team Charter

### 1. Purpose and Vision
* **Why We Exist:** To design and develop a South Africa-focused digital directory platform that connects local service providers (plumbers, electricians, builders, tutors) with clients seeking verified, affordable local services.
* **Mission:** Deliver a responsive web application featuring freemium and paid subscription tiers (R0 Basic vs R299/month Pro tier), guided quote request wizards, lead management dashboards, and transparent review workflows.
* **Success Definition:** 
  - Service providers can register, choose a subscription plan, and customize their business profile details.
  - Clients can search directory listings by service category/location and submit quote inquiries.
  - Pro tier benefits (top search placement, verified badges, unlimited photos) operate according to subscription status.
  - Development tasks and user stories are tracked on visual taskboards.

### 2. Team Roles and Responsibilities
* **Zusiphe Precious Mvovo (Developer & Portfolio Author):** Frontend component architecture (React, Tailwind CSS), subscription workflow UI, business dashboard interfaces, directory search filters, and GitHub portfolio maintenance.
* **Peer Collaborators / Mentors:** Code review, guidance, and testing feedback.

### 3. Ways of Working (Agile Framework)
1. Maintain project backlog items in visual taskboards (categorized into To Do, In Progress, and Completed).
2. Break down user stories into focused technical tasks with defined acceptance criteria.
3. Move active tasks across workflow columns as development progresses.
4. Conduct regular stand-up updates to report completed work, upcoming tasks, and technical blockers.
5. Apply the **Definition of Done** before marking any feature or interface as complete.

### 4. Working Agreements
* **Task Ownership:** Take responsibility for assigned frontend and database tasks and update task status immediately when work changes.
* **Communication:** Use agreed channels (WhatsApp, GitHub) for daily updates, code commits, and formal reviews.
* **Blocker Escalation:** Raise technical impediments, layout issues, or integration bugs as early as possible.
* **Feedback:** Review work against requirements and apply constructive feedback to improve code quality.

### 5. Definition of Done (DoD)
A task or feature is considered **Done** only when:
- The user interface meets the specified design and functional requirements.
- Layouts are tested and verified across desktop and mobile views.
- Known critical UI bugs or input handling issues are resolved.
- Associated documentation, screenshots, and portfolio evidence files are updated.
